# 部署维护说明

## 更新与检查

先备份数据库、附件和 `.env`，在独立副本安装依赖并运行 `npm run lint`、`npm run build`、`npm test`。校验通过后统一更新程序及依赖，再重启服务。保留运行数据；无需同时重启外网隧道。

依赖安全分开检查：`npm audit --omit=dev` 检查运行依赖，`npm audit` 同时检查开发工具。不要直接运行带 `--force` 的自动修复。

## 登录保护

登录和注册只统计失败尝试：同一来源及账号5分钟内最多12次，同一来源累计最多60次。超过限制返回429和等待时间；成功操作不消耗失败额度，数据库同步、上传下载及业务登记不参与限速。

默认仅信任回环地址的代理，读取其追加或覆盖的 `X-Forwarded-For` 最后一项。直接访问者自行提供的转发头不受信任。反向代理应追加真实客户端IP或覆盖客户端传入的转发头。

代理与平台分开部署时，可在 `.env` 的 `AUTH_TRUSTED_PROXY_IPS` 填写明确的代理IP，用逗号分隔。留空表示不信任代理头；不接受通配地址和网段。此设置不改变Express的全局 `trust proxy`。

## 前端与接口

正式环境前端和API同源；开发环境由Vite代理 `/api`，后端端口可通过 `API_PORT` 设置。未开放通用跨域访问。

Tailwind构建依赖已移除，原有浏览器基础样式保留在 `src/base.css`，页面继续使用自定义样式。搜索使用标准Custom Highlight API，并保留回退显示。

## 仓库维护

提交身份使用GitHub的隐私邮箱。更新尽量在分支中一次提交完整文件，检查通过后合并；可将 `Source checks` 中的 `check` 作业设为 main 合并前的必要检查；启用后通过分支提交并合并。分支保护与历史重写需仓库管理员操作，不能仅靠上传源码生效。

本版本保留管理员将密码重置为 `123456` 的既有规则。重置后提醒本人修改；随机临时密码及强制改密需另行调整业务流程。

## 账号会话

修改或重置密码会递增该账号的session_version，立即拒绝旧凭证并断开该账号的通知连接；其他账号不受影响。更新时自动补齐数据库列，保留原账号与数据。旧版本凭证在首次改密或账号状态变更前继续有效，无需全员重新登录。全局auth_version机制继续保留。闲置的gate/entry-token接口及相关配置读取已移除。

停用、改为待审核及重新启用账号时会撤销原有登录，并断开通知连接。状态更新和审计在同一事务中完成。登录先验证密码：账号不存在和密码错误统一返回“账号或密码错误”，密码正确后才提示待审核或停用状态。
