# 维护与更新

使用者操作见网站“帮助文档”；程序入口见`docs/CODE-MAP.md`。

## 运行与备份

Node提供网页和API，SQLite保存业务数据，`server/uploads`保存附件。修改`src`不会立即改变已发布页面，修改后端需要重载Node。

| 位置 | 内容 |
| --- | --- |
| `server/data/lab_platform.db` | 业务数据库 |
| `server/uploads` | 照片和附件 |
| `.env` | 本机密钥、注册码、端口等配置 |
| `src/config` | 平台名称、菜单和房间等部署设置 |
| `dist` | 已发布网页；旧哈希资源供已打开的浏览器继续读取 |
| `server/logs` | 运行、启动、监测和更新记录 |
| `server/backups` | 启动时及每小时生成的数据库与配置快照，成套保留72份 |

每个数据库快照旁的同名`.db.config`目录保存`.env`、`src/config`下的JSON配置及文件校验清单；自动备份不含照片。恢复配置时取同一时间戳的副本。旧版遗留的已完成备份空日志文件会自动清理。

完整备份运行`npm run backup`，保存到项目同级的`项目名-backups/full-时间戳`。包含数据库、附件、配置、程序和构建，附完整性与附件检查结果；不复制可重新安装的依赖。将完整备份另存到其他磁盘或私有存储。

## Windows程序更新

1. 在独立目录准备新版本，安装锁文件中的依赖，保留运行版的`.env`和`src/config`设置。只在需要验证真实数据时使用私有备份，通常使用自动测试中的虚构数据。
2. 在候选目录运行`npm run lint`、`npm test`、`npm run build`和`npm run test:ui`。浏览器测试首次执行前运行`npx playwright install chromium`。
3. 在运行目录执行：

   ```powershell
   npm run update -- --from D:\candidate-platform
   ```

4. 工具先验证并完整备份，然后暂停自动恢复、替换程序并集中重载Node；隧道保持运行。健康检查失败会恢复原程序，业务数据库和附件保留。结束时输出本次备份位置。
5. 核对`/api/health`、登录、同步、附件和主要业务页面，记录版本及备份位置。

更新工具在备份或停服前核对运行依赖声明、锁文件的直接及间接依赖版本和已安装版本；只有开发依赖变化时可以继续。缺少锁文件或版本不一致会中止更新。工具适用于运行依赖未变化的Windows部署。依赖变化时，先在独立目录完成安装和全部验证，最后安排一次维护窗口停止Node、更换程序及依赖、启动并验证；失败则恢复原程序及依赖。其他操作系统由其服务管理器负责停止和启动Node。

仅回滚程序：

```powershell
npm run update -- --rollback D:\platform-backups\full-时间戳\project
```

该命令保留当前数据库和附件。涉及不兼容数据库结构的版本，应使用该版本专门的数据恢复方案。

## 数据恢复

先备份当前状态，停止Node和监测任务；把当前`server/data`整体移到临时保留目录，恢复成套数据库与附件。按备份锁文件安装依赖、构建并启动，核对数据库完整性、库存和附件后恢复监测。不要将旧数据库与新的WAL/SHM混放。

## 启动与监测

已有启动入口只启动缺失服务。程序构建使用`npm run build`：新资源写完后才替换入口，构建失败时原页面仍可使用。

Windows后台管理入口为`scripts/service.ps1`，首次安装按README使用管理员PowerShell。监测同时检查网页资源和数据库API。安装为S4U后台任务后可在开机、注销桌面时运行；更换Windows账户或机器后重新安装并核对运行结果。工作站需保持开机、联网和不休眠。

更新期间`server/logs/maintenance.json`标识更新进程，监测不会争抢重启服务。异常退出后标记失效，后续检查可继续恢复。

## 故障定位

| 现象 | 依次检查 |
| --- | --- |
| 本机也打不开 | Node进程、端口、磁盘、安全软件、服务错误日志 |
| 本机正常，公网502 | 本机网络、隧道、云端转发和域名入口 |
| 网页正常，操作失败 | API响应、数据库、对应服务日志 |
| 同步慢 | 是否首次读取、网络耗时、并发操作和磁盘状态 |

提交超时先核对是否保存，再决定重试。记录发生时间、模块、单号及报错，便于定位。

## 版本与更新记录

以 2026 年 10 月 23 日整体工作台改版为 `2.0.0` 起点；之后的历史版本按已完成更新回执整理，新更新逐批记录。在使用帮助中，选择“平台维护”后的“更新日志”查看历次变化。

按每批实际更新的最高变更级别准备一次版本：

| 级别 | 适用变更 | 示例 |
| --- | --- | --- |
| 大版本 `major` | 整体界面、核心流程或架构改版 | `2.0.0 → 3.0.0` |
| 功能版本 `minor` | 新增模块、功能或重要交互 | `2.0.0 → 2.1.0` |
| 修复版本 `patch` | 修复问题、文案及局部样式调整 | `2.0.0 → 2.0.1` |

在开发副本完成修改后执行，例如 `npm run release -- patch "修复手机布局"`。工具同步包版本、累计次数和 [更新记录](CHANGELOG.md)，准备发布候选；再按正常流程测试、备份和发布。一次更新里的多项修改合记一批，重新构建、测试重跑和重复部署沿用同一候选。

`npm run release -- --check` 只检查记录；构建也自动检查版本一致性。侧栏顶部读取包版本，帮助页更新日志按 `src/config/release-history.json` 计算累计次数。历史基线按已保存的完成回执汇总，过去未记录的版本号不补造。
